生配信やライブイベントの本番では、スケジュール通りに進行しない場面（開始の遅れ、スピーチの延長、時間調整など）が頻繁に発生します。 \
Ontime は、本番中に発生するこれらの遅延や時間変化を正確に把握し、チーム全体で共有するための多彩なツールを提供しています。

遅延管理における 4 つの主要概念：
- [追加時間 (Added time)](#追加時間-added-time) 
- [見込み時刻 (Expected time)](#見込み時刻-expected-time) 
- [スケジュール遅延 (Scheduled delays)](#スケジュール遅延-scheduled-delays)
- [オフセット / 遅延時間 (Offsets)](#オフセット-offset)

## 追加時間 (Added time)

エディタ画面の操作または API 経由で、現在実行中のイベントに対して手動で時間を追加（または短縮）できます。

これは最も手軽な遅延調整方法です。 \
「追加時間」を設定すると、元の進行表スケジュールを変更することなく、`オフセット` と `終了見込み時刻` が自動調整されます。

## 見込み時刻 (Expected time)

`見込み時刻` は、現在の進行ペース、累積した `オフセット`、および `スケジュール遅延` を加味して自動計算される **「実際の開始・終了予定時刻」** です。 \
（例: 「現在の押し具合からすると、後続のイベント X は何時何分に始まる見込みか」）

## スケジュール遅延 (Scheduled delays)

`スケジュール遅延` は、進行表エントリとして明示的に挿入される計画的な時間調整ブロックです。

追加時間とは異なり、全体のスケジュール構造を壊すことなく、進行表の特定箇所に遅延レイヤーを適用します。 \
元の予定時刻を保持したまま、「ここで10分間の押しが発生している」という事実をチーム全員に明確に伝達できます。

また、必要に応じてスケジュール遅延を確定させて、進行表の正式な予定時刻として統合（適用）することも可能です。

:::note[遅延の伝播 (Propagation)]
`スケジュール遅延` は後続のイベントへと自動的に伝播します。 \
後続の進行表に遅延を吸収できるだけの十分な「空き時間（ギャップ）」が見つかるまで、後続イベントの開始見込み時刻を後ろ倒しにし続けます。
:::

## オフセット (Offset)

`オフセット` は、現在の実際の進行状況が元の予定スケジュールからどれだけ乖離しているか（進み/遅れ）を示します。

- プラスの値: 予定より早く進行している（巻き）
- マイナスの値: 予定より遅れて進行している（押し）

:::note[終了までカウント (Count to end) との併用]
`Count to end`（終了までカウント）が有効なイベントは、開始時刻が遅れた場合でも本来の終了予定時刻に合わせて残り時間を縮めてカウントダウンします。 \
そのため、定刻通りに終了する限りオフセットは発生しません。

本番開始時刻や完全撤収時刻など、動かせない「絶対的なデッドライン」を持つイベントに最適です。
:::

### 絶対モード (Absolute mode)

絶対モードは、Ontime におけるオフセット計算のデフォルト設定です。

現在のシステム実時刻（時計）と進行表の予定時刻を比較し、現在どれだけ巻いているか/押しているかを計算します。

#### 絶対モードでの計算例

:::tip[遅れて開始し、後続に空き時間がない場合]
予定より10分遅れて開始した場合、`オフセット` は `-00:10:00`（10分の遅延）を表示します。

```
| 実際の進行状況                | 計算結果                      |
| ----------------------------- | ----------------------------- |
| 現在時刻: 09:10               | 予定開始時刻: 09:00           |
| イベントA 実際の開始: 09:10   | 予定終了時刻: 10:00           |
| 進行表:                       | 実際の開始時刻: 09:10         |
| - イベントA 9:00 -> 10:00     | 終了見込み時刻: 10:10         |
| - イベントB 10:00 -> 11:00    | オフセット: -00:10:00         |
```
:::

:::tip[遅れて開始したが、イベントが「終了までカウント」に設定されている場合]
`Count to end` イベントは本来の終了時刻（10:00）に合わせてカウントダウンするため、オフセットは `00:00:00` のままとなります：

```
| 実際の進行状況                | 計算結果                      |
| ----------------------------- | ----------------------------- |
| 現在時刻: 09:10               | 予定開始時刻: 09:00           |
| イベントA 実際の開始: 09:10   | 予定終了時刻: 10:00           |
| 進行表:                       | 実際の開始時刻: 09:10         |
| - イベントA                   | 終了見込み時刻: 10:00         |
|   予定: 9:00 -> 10:00         | オフセット: 00:00:00          |
|   タイプ: count-to-end        |                               |
| - イベントB                   |                               |
|   予定: 10:00 -> 11:00        |                               |
|   タイプ: count-down          |                               |
```

※もしこのイベントが予定終了時刻（10:00）を超過（オーバータイム）した場合は、その超過分がオフセットとして計上されます。
:::

### 相対モード (Relative mode)

相対モードは、進行表の予定開始時刻を無視し、**「進行表が実際に開始された時刻」** を基準にしてオフセットを計算します。

リハーサル、事前収録、準備進行など、実時刻の何時にスタートしたかは重要ではなく、進行中の所要時間の伸び縮みだけを追跡したい場合に便利です。

:::tip[00:00:00 から進行表を開始する場合]
進行表を `00:00:00` スタートで作成することがあります。 \
**絶対モード** では `00:00:00` は「深夜0時」と解釈されるため、現在時刻との差分で巨大なオフセットが表示されてしまいます。

**相対モード** を使用すると、実際に進行を開始した瞬間を基準として計算されるため、`00:00:00` スタートの進行表でもオフセット `00:00:00` から正しく計測を開始できます。
:::
