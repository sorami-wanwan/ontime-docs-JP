title: オートメーション (Automation)

---

オートメーション機能は、Ontime をユーザーの制作ワークフローに統合するための強力なシステムです。 \
進行表にはイベントや登壇者、演出に関する大量の情報が集約されています。オートメーションを活用することで：

- Ontime の進行状況やデータを外部機器に自動配信
- イベントの再生・停止などのタイミングを外部ソフトウェアに通知
- 音響、照明、スイッチャー、メディアサーバーなど他ツールとの同期自動化

設定は `エディタ` -> `設定` -> `オートメーション` から行えます。

## オートメーションの設定方法

オートメーション機能は、**[オートメーションの管理](#オートメーションの管理-manage-automations)** と **[トリガーの管理](#トリガーの管理-manage-triggers)** の 2 つのパートで構成されています。

### オートメーションの管理 (Manage automations)
オートメーションのエントリには、**フィルター条件（ロジック）** と **出力（送信メッセージ）** を定義します。 \
（例: 「特定の条件を満たしている場合のみ、このメッセージを送信する」）

![Network settings](../../../../assets/screenshots/editor/settings/automation__create-automation.png)
上記画面の例では、カスタムフィールドに値が存在する場合にのみ、その値を引数として OSC メッセージを送信する設定を行っています。

:::note[HTTP、OSC、および Ontime 内部アクション]
OSC メッセージの送信だけでなく、外部への HTTP リクエスト送信や、Ontime 内部のアクション（AUXタイマーの開始・停止など）も自動化できます。
:::

### トリガーの管理 (Manage triggers)
トリガーは、定義したオートメーションを Ontime のイベントライフサイクル（再生イベント）に関連付けます。 \
（例: 「Ontime でどのような操作や状態変化が起きたときに、どのアクションを実行するか」）

![Network settings](../../../../assets/screenshots/editor/settings/automation__create-trigger.png)
上記画面の例では、「Ontime でイベントが開始されたときに、音響再生を開始するオートメーションを実行する」というトリガーを定義しています。

### Ontime ライフサイクルイベント一覧

Ontime の本番再生中に発生するライフサイクルトリガーは以下の通りです：

| イベント名            | 説明                                                               | 
| :-------------------- | :----------------------------------------------------------------- |
| `On Load`             | イベントがスタンバイ（ロード）されたときに発火                     |
| `On Start`            | イベントが再生開始されたときに発火                                 |
| `On Pause`            | イベントが一時停止されたときに発火                                 |
| `On Stop`             | プレイバックが停止されたときに発火                                 |
| `On Every Second`     | 1秒ごとに毎回発火                                                  |
| `On Update`           | タイマーが動作している間、1秒ごとに発火                            |
| `On Finish`           | タイマーが 00:00 を通過した瞬間に発火                              |

### オートメーションでの変数の使用

送信メッセージ内に `{{ontime-data}}` というテンプレート構文を埋め込むことで、Ontime のランタイム変数を動的に挿入できます（例: `/your-message/{{ontime-data}} {{ontime-more-data}}`）。

[ランタイムデータ](/api/data/runtime-data/) で定義されているすべてのデータ項目をペイロードとして送信できます。

トリガーが発火すると、Ontime はテンプレート部分をその時点の最新データに自動置換して送信します。

:::tip[メッセージの例]
ロードされたイベントのインデックス番号を付与して送信する場合：

```
/send-this/loaded-event-{{runtime.selectedEventIndex}}
```
:::

:::note
括弧内のテンプレート名は、[ランタイムデータ](/api/data/runtime-data/) に記載された階層構造と完全に一致させる必要があります。 \
ネストされたオブジェクトのキーは `.` で繋ぎます：

`{{eventNext.note}}` \
`{{playback}}` \
`{{timer.current}}`
:::

### 利用可能な変数の一覧

[ランタイムデータ](/api/data/runtime-data/) のすべてのプロパティが変数として利用可能です。 \
[カスタムフィールド](/features/custom-fields/) も同様に変数のリストに追加され、カスタムフィールドパネルで設定したキー名で参照できます。

:::note[現在の変数構造を調べる方法]
ブラウザで `http://<IPアドレス>:<ポート番号>/api/poll` にアクセスすると、現在のアプリケーション状態の完全な JSON オブジェクトが返されます。

例えば JSON レスポンスに以下の構造が含まれている場合：
```
payload {
    eventNow: {
        id: "1234"
    }
    eventNext: {
        custom: {
            vfx: "VFX3"
        }
    }
}
```
テンプレート変数は `{{eventNow.id}}` および `{{eventNext.custom.vfx}}` と指定します。
:::

### 人間が読みやすい形式の変数 (Human-readable data)

通常のランタイム変数はすべてミリ秒単位（ms）で返されるため、人間が読むテキストメッセージとして外部画面に送信する場合には扱いづらいことがあります。

そのため、Ontime では `hh:mm:ss` 形式に整形された便利な変数を別途提供しています：

| 変数名               | 構文                       | 出力形式 / 説明                                                       |
| :------------------- | :------------------------- | :-------------------------------------------------------------------- |
| `human.clock`        | `{{human.clock}}`          | 現在時刻（`hh:mm:ss`）                                                |
| `human.duration`     | `{{human.duration}}`       | 現在タイマーの総所要時間（`hh:mm:ss`）\*                              |
| `human.expectedEnd`  | `{{human.expectedEnd}}`    | 現在イベントの終了見込み時刻（`hh:mm:ss`）\*                          |
| `human.runningTimer` | `{{human.runningTimer}}`   | 実行中タイマーの残り時間（`hh:mm:ss`）\*                              |
| `human.elapsedTime`  | `{{human.elapsedTime}}`    | 実行中タイマーの経過時間（`hh:mm:ss`）\*                              |
| `human.startedAt`    | `{{human.startedAt}}`      | 現在タイマーが開始された時刻（`hh:mm:ss`）\*                          |

:::note
\* イベントが読み込まれていない（スタンバイしていない）場合、タイマー変数は `null` を返します。
:::
