---
title: クラッシュと破損データの保護
description: 異常終了時の自動復旧とデータ整合性の保護
---

万一の不具合やアクシデントに備え、Ontime はデータの破損を防ぎ、本番進行を継続するための安全機構を備えています。

:::tip[データ保存ディレクトリの場所]
ユーザーディレクトリの場所は OS およびインストール方法によって異なります。 \
デスクトップアプリ版をお使いの場合、アプリメニューの `ファイル` -> `保存先ディレクトリを開く` から直接アクセスできます。 \
その中に `crash` フォルダや `corrupt files` フォルダが作成されます。

**Windows の場合:**\
`AppData/Roaming/Ontime/`

**macOS の場合:**\
`Library/Application Support/Ontime/`

**Linux の場合:**\
`Home/Ontime/styles/`
:::

## クラッシュログ (Crash logs)
万一 Ontime のプロセスが異常終了した場合、ユーザーディレクトリ内にクラッシュログが生成されます。

ログファイルを添付して GitHub Issue やメールでお知らせいただくことで、迅速な調査と修正が行われます。

## 異常終了からの自動復旧 (Recover on bad shutdown)
マシンの電源断やクラッシュなどによって Ontime が不意に終了した場合でも、次回起動時に前回の実行状態が自動的に復元されます。

Ontime を再起動するだけで、現在進行中のタイマーや再生位置が本来あるべき状態へと自動復旧します。

## 破損データの自動隔離と修復 (Refuse corrupt data)
Ontime はプロジェクトファイルを読み込む際、データの整合性を厳密に検証します。

外部ソフトウェアによる不正な書き込みやバージョンアップ時の不整合などで壊れたデータを検出した場合、パーサーは処理を中断して安全を確保します。

大切なデータを保護するため、Ontime は読み込み前にプロジェクトのバックアップを作成し、`corrupt files` ディレクトリに退避します。 \
その後、読み込み可能な部分を復元したファイルが `(recovered)` という名前で生成されます。

また、データ構造が変更された新バージョンへプロジェクトを移行した場合は、自動的に `(migrated)` というファイルが新規作成されます。
